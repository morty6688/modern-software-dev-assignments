# 第 2 周：为第三方 API 构建 MCP 服务器

## 作业概述

构建一个 MCP 服务器，将第三方 API 提供给你的编程智能体使用。对接 API 是相对简单的部分。评分重点是**智能体使用的便利性**：模型能否选对工具、正确调用，并在出错时恢复。此外，还需要实现可正常工作的 **OAuth** 流程，因为大多数值得封装的 API 并不接受静态密钥认证。

### 学习目标

- 为只能看到工具模式（schema）和描述的调用方**设计**工具接口。
- 在长期运行的服务器内**实现** OAuth 令牌获取、缓存和刷新。
- **观察**你的设计选择如何改变智能体的实际行为。

## 学习材料

- **[FastMCP](https://github.com/jlowin/fastmcp)**：你将使用的开发框架。
- **[MCP 规范](https://modelcontextprotocol.io/)**：工具注解、传输方式、错误语义。
- **[参考 MCP 服务器](https://github.com/modelcontextprotocol/servers)**：编写自己的服务器前，先阅读一个参考实现。

## 第一部分：构建服务器（25 分）

选择一个使用 **OAuth 2.0** 的 API：GitHub、Google（Gmail／Calendar／Drive）、Notion、Linear、Slack、Spotify 和 Strava 均符合要求。请选择你实际使用的服务，这样你更容易判断工具应该提供哪些功能。

要求：

- **至少 3 个工具**，而且必须能够**组合使用**：一个工具的输出可以作为另一个工具的输入（例如，`search_x` 返回的 ID 能传给 `get_x(id)`）。
- **至少一个写入工具**，能够修改真实状态。
- 代码放在 `week2/` 中，通过 stdio 运行，并能用一条已在文档中说明的命令启动。

## 第二部分：智能体使用的便利性（30 分）

这是本作业的核心。以下每项设计都围绕一个事实：智能体只能看到你的工具模式和文档字符串（docstring），*除此之外一无所知*。

- **将约束写进工具模式，而非文字说明。** `sort: Literal["stars", "forks"]` 优于 `sort: str` 加上一句文档字符串说明。如果工具模式与文档字符串不一致，智能体就会遇到无法解释的校验失败。
- **整理输出结构。** 不要直接透传原始 API JSON。请选择智能体所需的字段。原始载荷会消耗大量 token，还会让你的接口约定与他人的 API 耦合。
- **错误应作为数据返回，而非抛出堆栈信息。** 返回结构化、可据此采取行动的信息，并提供足够细节，让智能体区分*不应重试*（ID 错误）与*可以重试*（限流、短暂网络故障）。堆栈信息会结束智能体当前轮次，而 `{"error": "rate limited, retry after 42s"}` 不会。
- **文档字符串就是接口约定。** 说明 ID 来自哪里（例如“来自 `list_templates` 的数字 ID”），让工具可以串联。对于跨工具的工作流指导，请使用 `FastMCP(instructions=...)`。
- **写入工具需要制动机制。** 使用工具注解（为读取工具设置 `readOnlyHint`），并为执行不可逆操作的工具提供 `dry_run` 参数，或将其拆分为预览和提交两步。

## 第三部分：OAuth（25 分）

实现真实的 OAuth 流程，而不是粘贴一个 bearer token。

- 完整实现授权码交换，并**缓存**令牌，在到期时进行**静默刷新**。
- **最小权限范围（scope）。** 如果只读取数据，就只申请只读权限，并在报告中说明每个权限范围的必要性。
- **仓库中不得包含秘密信息。** 从第一次提交开始，就通过环境变量读取这些信息。提交 `.mcp.json.example`，将真实配置文件加入 gitignore。
- **处理令牌在会话中途失效的情况。** 长期运行的服务器不得在工具调用过程中尝试打开浏览器，而应返回可据此采取行动的错误信息。

## 第四部分：集成与演示（20 分）

- 将服务器注册到 Claude Code 或 Cursor，并提交配置（`.mcp.json.example`）。
- **展示一份端到端交互记录**，其中智能体至少串联两个你编写的工具来回答一个真实提示词。记录应包含提示词、实际调用的工具及参数，以及结果。
- **展示一次失败**及你的错误设计如何处理它。必要时可主动触发失败（如错误 ID、已撤销的令牌）。
- 至少有一个测试**通过 MCP 协议**测试服务器，而不是仅调用 Python 函数。
