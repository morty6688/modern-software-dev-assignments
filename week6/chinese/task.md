# INC-2207：商户收到同一笔付款两次

## 情况报告

商户 `m_maple` 本周有几笔付款收到了两次通知，表现为收到两条事件 ID 不同的 Webhook。另有几家商户也报告了同样的问题。

## 交付要求

**1. 修复。** 你需要交付：

- 更新 `app/services`，修复导致付款通知重复的根因。
- 对重复事件，自动取消尚未完成的投递，包括已经进入投递队列的投递。已取消的投递无须以已投递（`delivered`）或投递失败终止（`dead`）状态结束。整个过程无须人工跟进。

部署要求：

- 保持对旧版消息总线消息的兼容性。
- 同一个版本会部署到所有区域。目前只有这一个区域的日志。

**2. 影响范围报告。** 对每个商户和幂等键的组合，将 API 最早接受的事件视为原始事件，将该组合下此后被接受的每个事件视为重复事件。列出这些重复事件中至少收到一次 2xx 响应的投递，无论原始事件是否已投递或何时投递。将结果写入 `out/impact.json`：

```json
{
  "affected": [
    { "event_id": "evt_…", "endpoint_id": "ep_…", "delivery_ids": ["dlv_…"] }
  ],
  "totals_minor": { "USD": 0, "EUR": 0 },
  "skipped_rows": 0
}
```

- `affected` 中每个重复事件与端点的组合对应一条记录。
- `totals_minor` 按币种汇总这些记录对应的事件金额，以各币种的最小货币单位计。省略没有记录的币种。
- `skipped_rows` 是 `incident/` 中损坏的记录行数。

## 客服备注

`m_maple` 的 SDK 重试很频繁。我们已经请他们降低重试频率。
