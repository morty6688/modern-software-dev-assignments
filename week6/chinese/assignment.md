# 第 6 周：优化智能体运行成本

本文中的命令和文件路径均以 `week6/` 为起点。[练习工单](task.md)和 [作业报告模板](writeup.md)也有中文版本。

## 作业概述

本次作业要求你调优一套编程智能体配置，用它处理生产代码库中的事故。优化目标有两个：

- **正确**解决事故。
- 以**尽可能低的成本**解决事故。

本次作业只支持 **Claude Code** 和 **Codex** 两种智能体运行框架。为便于比较成本，只能在这两种框架中使用作业**费率表**所列的模型，详见下文。

调优完成后，将配置提交给自动评分器。评分器会在同一个代码库中用一个未公开的事故运行这套配置，按输出的正确性评分，并按 token 用量计算成本。

> 注意：你的配置必须能在无头模式下独立运行。自动评分期间没有用户输入。

本次作业使用 Switchyard，一个 Webhook 投递系统。

### 学习目标

- **测量**一次智能体运行的成本，弄清 token 花在了哪里。
- 在能力和成本之间**有意识地取舍**，例如选择模型、推理强度、上下文和任务拆分方式。
- **构建**一套无需人工干预的配置，让它也能处理调优时没见过的任务。

### 可信信息来源

处理 Switchyard 的事故时，以作业根目录的 `task.md` 为准确定交付目标，以 `app/contracts/` 为准确定系统必须满足的行为。调优时，如果仓库中其他材料与这些要求不一致，可能需要依据这些要求处理分歧。

事故工单 `task.md` 可能给出初步诊断或建议。把它们当作调查线索，用契约、代码和事故证据加以核实。

## 学习材料

- **[Claude Code 无头模式](https://code.claude.com/docs/en/headless)**、**[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)**：介绍两种框架如何在没有终端的情况下运行。
- **`rate_card.json`**：所有允许使用的模型的价格。本次作业期间费率固定。

## 评分运行流程

评分器将你的 `week6/` 目录复制到一个新容器中，然后在该目录下运行：

```bash
./run.sh task.md
```

运行使用无特权用户和空的主目录，没有交互式终端，**时限为 10 分钟**。

每次运行前，评分器都会**用自己的副本替换 `app/`、`incident/` 和 `task.md`**，并排除 `tools/starter/` 和 `out/`。`week6/` 里的其余文件都会按你提交的内容原样使用，包括 `run.sh`、提示词、根目录的 `AGENTS.md` 或 `CLAUDE.md`、技能、钩子、子智能体定义和辅助脚本。

### 配置放在哪里

评分器会在启动 `run.sh` 之前换入自己的 `app/`，因此提交到 `app/` 里的修改不会应用到评分环境。不过，在启动智能体之前，`run.sh` 仍可以改写、替换或删除工作目录中的任何文件，包括 `app/` 下的文件。

### 评分对象

`run.sh` 退出后，评分器从工作区取出两项结果：

- **修复结果。** 将 `app/services/api`、`app/services/router` 和 `app/services/worker` 复制到一份干净的发行版本中，再运行隐藏测试。
- **影响范围报告。** 将 `out/impact.json` 与 `incident/` 中记录的实际情况进行比较。

| 分数 | 计算方式 |
| --- | --- |
| `repair`（修复） | 与本次事故相关的场景通过率 × 其他场景的通过率。 |
| `impact`（影响范围） | 0.6 × 受影响条目集合的 F1 分数 + 0.4 × 报告中完全正确的数值所占比例。 |

两项分数**均为 1.00** 时，本次运行才算通过。未公开的事故也按相同方式评分，使用该事故自己的测试场景和证据。

### 运行框架和模型

评分器安装了固定版本的 **Claude Code** 和 **Codex**。你可以任选一种，也可以在同一个 `run.sh` 中使用两种框架。

所有模型调用都经过课程网关。网关只接受费率表中的模型：

| 模型 | 档位 | 输入 | 输出 | 缓存读取 | 缓存写入 |
| --- | --- | --- | --- | --- | --- |
| `claude-sonnet-5-5` | 中档 | $2.00 | $10.00 | $0.10 | $2.50 |
| `claude-haiku-5-5` | 小型 | $0.10 | $0.50 | $0.01 | $0.125 |
| `gpt-6.1-terra` | 中档 | $1.00 | $5.00 | $0.05 | $1.25 |
| `gpt-6-luna` | 小型 | $0.10 | $0.50 | $0.01 | $0.125 |

价格按每百万 token 计。请求其他模型会被拒绝，结果中会显示被拒绝的请求。

### `run.sh` 可以使用的环境

| 运行框架 | 评分环境 |
| --- | --- |
| Claude Code | 已设置 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_API_KEY`，可直接使用 `claude -p ... --model claude-haiku-5-5 --permission-mode bypassPermissions`。后台调用会使用 `claude-haiku-5-5`，按普通调用计量。 |
| Codex | `CODEX_HOME` 指向通过网关转发请求的配置。使用 `codex exec -m gpt-6-luna --dangerously-bypass-approvals-and-sandbox --skip-git-repo-check ...`。 |

这些环境变量里的密钥是占位值，真实密钥由网关持有。请勿在提交中放入自己的密钥。`tools/practice.py` 会设置相同的环境变量，因此练习时可用的 `run.sh` 在评分时也会看到同样的环境。

评分时无法使用费率表之外的模型、自行托管的模型或你的个人账号和登录状态，也无法执行任何需要你回应提示的步骤。

## 成本如何计算

对网关在本次运行中转发的每一个请求，分别将输入、输出、缓存读取和缓存写入的 token 数乘以各自的费率，再把费用相加。评分器忽略运行框架自行报告的金额，因此同一个模型通过不同框架调用时使用相同费率。每次都从冷启动开始：使用容器里的新用户和空主目录，没有上一次运行留下的缓存。

每次运行还有 **$2.00** 的预算上限。超过上限后，网关会拒绝进一步的请求。

## 第一部分：测量基线（作业报告占 10 分）

运行基线并记录结果：

```bash
python tools/practice.py --keep
```

这个命令将 `week6/` 复制到临时工作区（排除 `tools/starter/`），在其中通过网关运行 `./run.sh task.md`，按评分器的方式打分，并输出各类得分、成本和各模型的 token 用量。日志保存在 `runs/` 中。`agent.log` 记录 `run.sh` 的输出，`--keep` 还会将智能体对 `app/` 的修改保存为 `app.diff`，并保留它生成的 `out/` 目录。练习脚本只在副本中评分，评分器也从自己的副本开始。请保持你本地的 `app/` 整洁，练习过程不会修改它。

练习时，两种框架都可以使用你自己的登录凭据：Claude Code 使用你的 Stanford Claude 账号，Codex 使用你的 ChatGPT 账号（`codex login`）。也可以使用 `ANTHROPIC_API_KEY` 或 `OPENAI_API_KEY`。练习通过你的账号运行，无论采用哪种登录方式，网关都按费率表计量。

修改之前先读日志。Token 花在了哪里？智能体漏掉了哪些场景？它基于什么判断才走到了这一步？

## 第二部分：调优配置（作业报告占 20 分）

让智能体按这个系统的要求解决事故，同时降低成本。评分前不会被替换的部分都可以调整：

| 调整方向 | 示例 |
| --- | --- |
| 模型 | 改用小型模型，或更换模型供应商。 |
| 路由 | 由中档模型诊断，小型模型编辑。仅在检查失败时升级模型。 |
| 推理强度 | 为机械性的步骤降低推理强度。 |
| 上下文 | 在根目录添加 `AGENTS.md` 或 `CLAUDE.md`，提供仓库导航，告诉智能体应读哪些内容、跳过哪些内容。 |
| 任务拆分 | 在 `run.sh` 中进行多次无头调用，分别处理修复和报告。可以开启新会话，也可以延续现有会话。 |
| 工具 | 工具允许列表、技能、钩子、子智能体、解析证据的脚本。 |
| 验证 | 让智能体在停止之前执行你定义的检查。 |
| 缓存 | 保持提示词前缀稳定，让后续调用能够读取缓存。 |
| 停止条件 | 限制会话轮数，或在检查通过后停止。 |

尽量对每项改动多运行几次，确认表现是否稳定。配置不稳定可能导致隐藏测试得分偏低。

围绕系统的通用行为调优。评分时用的是你从未见过的事故，因此逐步指导智能体解决这张练习工单的提示词对评分没有帮助。请勿向智能体提供 `tools/starter/`，该目录包含练习工单的答案，使用它会让练习结果失去意义。

## 第三部分：自动评分（70 分）

将你的 `week6/` 文件夹上传到 Gradescope 的 **Assignment 6 (Autograder)**。只打包本周文件夹。从文件夹内部打包，例如 `cd week6 && zip -r ../week6.zip .`，以包含 `.claude/` 等隐藏目录。自动评分器会在未公开的事故上**运行一次**你的配置，按以下方式打分：

| 评分项 | 分值 | 评分方式 |
| --- | --- | --- |
| 正确性 | 35 | 根据修复和影响范围的分数评定。 |
| 成本 | 35 | 按比例计分。达到或超过基线成本为 0 分，降至基线成本的一半或更低为 35 分。 |

基线使用提供的 `run.sh`。课程团队在未公开的事故上测得的基线成本是**每次 $1.50**。

你可以看到修复和影响范围的分数、各类场景的通过数、运行耗时、成本、各模型的 token 用量和被网关拒绝的请求。未公开的事故、测试场景和智能体的输出不会展示。

自动评分**最多可提交三次**。Gradescope 会执行此限制，第四次提交不会运行。每次提交只进行一次评分运行，请先用 `tools/practice.py` 确认配置可用。以 Gradescope 上当前生效的提交为准。如果运行因评分器本身故障而失败，则不占提交次数。

**排行榜。** Gradescope 会用你选择的名字展示本次运行是否通过以及成本。通过的提交中，成本最低者可获得额外加分。

## 作业报告（30 分）

填写 `writeup.md`，推送到你的仓库，再将仓库链接提交到 Gradescope 的 **Assignment 6 (Writeup)**。报告可以不限次数地重新提交，请在最后一次自动评分后提交，并纳入该次评分的结果。报告涵盖第一至第三部分。评分依据是实验和推理的质量：你测量了什么、改了什么、为何这样改、结果如何，以及哪些结论可能适用于未见过的事故。最终分数的高低不影响这一部分的评分。
