# 第 3 周：编写一个技能（Skill）

## 作业概述

技能用于承载可重复执行的流程，也就是那些否则你每次都要粘贴到聊天中的检查清单。本周，你将编写一个技能，将它用于真实的开源仓库，并检查它是否会在恰当的时候触发，以及执行时能否可靠完成任务。

### 学习目标

- **识别**值得固化为技能、而非反复解释的工作流。
- **编写**一个描述能可靠触发、正文包含判断依据而不只是操作步骤的技能。
- **验证**它能在该触发时触发，并在执行时可靠完成任务。

## 第一部分：选择工作流（15 分）

选择一个你会**多次执行**的流程，而且其中至少包含一个真正需要判断的环节。单条固定命令是 shell 别名，不是技能。

如果不想自己设计，可以参考以下示例：

| 技能 | 功能 |
|---|---|
| 从 Issue 到实现计划 | 阅读 Issue，检查相关代码，指出含糊之处，生成分步计划 |
| PR 审查 | 按固定标准审查差异，引用准确的文件和行号，区分阻碍合并的问题与改进建议 |
| Bug 复现 | 构建最小复现，提出假设，运行针对性测试，然后才提出修复方案 |
| 编写测试 | 判断哪些行为需要测试，遵循仓库约定，编写并运行测试 |
| 熟悉仓库 | 针对“添加身份认证”等任务，帮助新开发者了解架构、命令和可能的修改位置 |
| 代码库迁移 | 将 Pydantic v1 升级到 v2 等迁移任务的检测规则和安全转换步骤固化下来 |
| 依赖升级 | 阅读变更日志，识别不兼容变更，应用修改并验证 |
| 从截图到实现 | 使用仓库现有组件，根据截图实现界面，然后进行视觉验证 |
| 性能排查 | 建立基线，在修改前进行性能分析，做一项针对性修复，再比较结果 |
| 安全审查 | 针对某一特定类别检查新增代码，要求提供证据，而非给出推测性的警告 |

先手动执行一遍。你无法将自己从未执行过的流程固化为技能。

## 第二部分：编写技能（60 分）

按照 Agent Skills 标准编写 `SKILL.md`，并放到你的智能体能发现技能的位置。Claude Code、Cursor 等工具都读取相同格式；请查阅你所用智能体的文档，确认它会查找哪个目录。评分要点：

- **能触发技能的描述。** 必须使用用户实际会输入的措辞，说明技能做什么，*以及何时应使用它*。大多数技能失败的原因是从未被触发。
- **包含判断依据，而非只有步骤。** 说明情况不明确时应如何判断，以及不应做什么。复述工具文档并不能提供新的指导。
- 对确定性的操作提供**准确命令**。
- **精简的正文。** 每次技能触发，正文都会加载到上下文中，因此应将较长的参考资料放到技能目录中的辅助文件里，并在正文中引用，而不是把所有内容直接写入正文。

## 第三部分：测试（25 分）

- **触发测试**：提供三个应当触发技能的提示词，以及一个很接近但*不应*触发的提示词。报告实际发生的情况。如果那个相近提示词也触发了技能，说明描述范围过宽。
- **执行测试**：在所选仓库中端到端使用该技能，并展示结果。

## 提交内容
